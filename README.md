# eks-infra

Terraform for the cluster the other repos deploy onto. Four modules, two
environments, OIDC to AWS with no stored keys.

```
modules/vpc    3 AZs, NAT per AZ in prod, S3 gateway endpoint
modules/eks    managed node groups, IRSA, KMS-encrypted secrets
modules/rds    Postgres, Multi-AZ, generated password in Secrets Manager
modules/s3     versioned, encrypted, TLS-only, lifecycle tiering
envs/prod      the above, sized and guarded for production
envs/staging   the same modules, cheaper, guard rails off where it is safe
```

## Decisions that cost or save real money

**NAT gateway per AZ in prod, one shared in staging.** A shared NAT is a
cross-AZ data charge on every egress byte plus a single point of failure.
In staging that trade is worth about $90/month and nobody is paged for it.
In prod it is not.

**S3 gateway endpoint on the private route tables.** Free, and it keeps S3
traffic off the NAT entirely. NAT data processing is billed per gigabyte, so
on a workload that reads from S3 all day it is usually the line worth
attacking first.

**Spot for Spark executors, on demand for general.** The Spark group is
tainted `workload=spark:NoSchedule` so nothing lands there by accident, and
the streaming drivers do not tolerate it. A driver evicted mid-batch loses the
checkpoint lease; an executor evicted is retried.

**Staging runs entirely on spot.** A node going away there is a useful
rehearsal rather than an incident.

## Decisions that prevent an outage

**`max_unavailable = 1` on node group updates.** The default of 25% sounds
faster, and on a three-node group it drains a third of the capacity at once.
Anything with a PodDisruptionBudget it cannot satisfy turns a rolling upgrade
into an outage.

**`ignore_changes = [scaling_config[0].desired_size]`.** The cluster
autoscaler owns the desired size after creation. Without this, every plan
proposes scaling the cluster back to whatever number is committed in git, and
eventually somebody approves it at 4pm on a Friday.

**The Kubernetes API is public but CIDR-restricted, and a variable validation
rejects `0.0.0.0/0`.** Fully private means a bastion for every `kubectl`,
which in practice means a long-lived bastion nobody patches.

**`skip_final_snapshot = false`, always.** The one time it is skipped is the
time it was needed. `final_snapshot_identifier` carries a timestamp, so it is
in `ignore_changes` or every plan shows a diff.

**The CloudWatch log group is declared, not left to EKS.** EKS creates it on
first write with retention set to never expire, which is a slow and invisible
bill.

## Secrets

The RDS master password is generated by Terraform, written to Secrets Manager,
and read by applications through IRSA. It is never in a tfvars file and never
committed. It is in state, which is why the state bucket is encrypted and
access to it is the same thing as database access.

`override_special` excludes the characters RDS rejects in a master password.
Finding that out costs eight minutes of a failed apply.

## CI

Static checks on every push: `fmt -check`, `tflint`, `tfsec` with
`soft_fail: false`. Then `validate` for both environments with
`-backend=false`, so it needs no credentials and takes no state lock.

Pull requests get a staging plan posted as a comment. `main` applies to prod
behind a GitHub environment that requires a reviewer. Prod never applies
unattended, whatever the pipeline would otherwise permit.

State locking is S3 native (`use_lockfile = true`), not the DynamoDB table
every older module still drags along.

## Running it

```bash
make validate ENV=staging
make plan     ENV=staging
make apply    ENV=staging
make bootstrap ENV=staging     # ingress-nginx, cert-manager, autoscaler
```

The bootstrap script discovers node groups by tag, so adding a group in
Terraform needs no change there.
